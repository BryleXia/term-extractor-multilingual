# 术语抽取流水线

**从句对齐的双语语料里抽术语，产出「可直接入库」的双语术语表 —— 每条术语同时带它在原句里的
逐字切片、和它的词条形式，两者各过各的闸门。**

## 它做什么

输入是**句对齐的双语语料**（`align.qc.json`，一句原文对一句译文），
输出是一批 `.xlsx` 术语表：每一行是一条术语，带它在**原句里的位置**、
它的**词条形式**、以及**类型标签**。

![流程图：已对齐的语料先过八道开跑前闸门，再以并发 40 派发，经逐字锚定检查、形态校验、交付门禁，产出 9 列 xlsx。无法锚定的术语被丢弃并记账；会交出残缺包的一轮直接退出码 3。](docs/pipeline-flow.svg)

跑过的规模：

| | 产出文件 | 句对 | 术语行 |
|---|---|---|---|
| 中文 ↔ 西班牙语 | 531 | 56,110 | 71,097 |
| 中文 ↔ 法语 | 554 | 65,097 | 69,719 |
| 中文 ↔ 俄语 | 533 | 57,469 | 69,578 |
| **合计** | **1,618** | **178,676** | **210,394** |

## 最难的一处：两套形式，而且不可互推

这是整个项目里唯一一个「怎么做都别扭」的问题，最后是**用两列解决**的。

术语必须同时满足两个互相矛盾的要求：

- **要在原句里定位。** 下游要把术语内联标回句子里
  （`当前[世界经济]{term}面临[新质生产力]{hot}转型压力。`），
  程序得拿术语字符串去原句里找。所以它必须是**句中逐字原样** ——
  改一个标点都会让它落在原句之外。
- **要能进术语库。** 术语库按国际术语规范收**词典形**：名词用单数、
  动词用不定式、有格的语言还原到主格。而句子里出现的是变格/变数之后的形式。

**两者不可互相推导** —— 从句中原样还原词典形要做形态分析（正是这一步在做的），
反过来要定位也必须知道原样。实测两列不同的比例：

| 语种 | 两列不同 | 为什么 |
|---|---|---|
| 西班牙语 | 20.6% | 单复数 |
| 法语 | 19.7% | 单复数 |
| **俄语** | **64.9%** | **6 个格还原到主格** |

**只交一列的话，必然有一边用不了。** 所以产出 9 列，第 4/5 列交句中切片、
第 8/9 列交词条形式，并加了一条门禁：**第 4/5 列必须 100% 逐字出现在所在整句里**。

## 反幻觉：不给模型「编」的机会

- **逐字锚定是硬闸门**：模型给出的术语若无法在原句里逐字定位，先让它改一次；
  仍不行就**丢弃并记账**。三语 210,394 行里**丢弃 1 条**。
- **形态还原有词典出处，不靠模型自觉**。词条形式要过第二道校验
  （`check_lemma_romance` / `check_nominative`，走 simplemma / pymorphy3）；
  不合格**回落成句中形式并记账，绝不丢术语**。
- **「习惯用复数」的词有一份带出处的清单**（`plural_lexicon.py`）：
  `derechos humanos`、`Nations Unies`、`осадки` 这类不能压成单数。
  每一条都附**词典或官方文本的出处 URL**，不是拍脑袋列的。

## 工程：八道闸门 + 三道熔断

一次全量是**几小时、真金白银**的运行，所以**宁可停下，不可跑错**。

**跑之前** —— 形态分析器在不在 → 输出名会不会撞 → 语料完整性对不对得上 →
输出目录有没有陈旧产物 → 墙钟是不是超了 → 磁盘够不够 →
**key 与模型是不是真能用**（发一次真请求探针）。

**跑之中** —— **花费熔断**（只停派发、不杀在飞批）→ **429 熔断**（绝对量 +
占比双条件，避开冷启动抖动）→ **余额熔断**（第一次命中就停，因为它是终局而非瞬时）。

**跑之后** —— 失败批比例超阈值就**不产出交付包**（退出码 3），
而不是交一个残缺的包。

## 可复现

- **模型响应全量落盘缓存**，键 = 模型 + 档位 + 提示词哈希 + 文件 md5 + 批内容哈希。
  改**交付层**（列配置、归一化、排序、打包）**不换键** —— 实测重导全局
  **零调用、30 秒**。改**提示词**才需要重跑。
- **断点续跑**：中断后重跑同一条命令，已完成的批走缓存不重复计费。

## 验证

- **922 条断言**（`python -m getterms.tests`，内部副本口径），
  其中含四条**已证伪检测器的反例断言**。
- **六个端到端脚本**（`e2e/`）：真跑主流程、只把 LLM 客户端换成假的或把 HTTP 层打桩，
  **零 API 调用**。覆盖交付列对位、行序、花费熔断、429 熔断、余额熔断、缓存副作用。
- **交付门禁**（`getterms/verify.py`）：逐文件检查表头、列名、类型白名单、
  逐字可定位、形态还原是否合法。

> **这个项目里最花时间的不是写代码，是「证明代码是对的」。**
> 交付之后又用六个只读子代理把产出逐文件复核了一遍，
> 公开记录了**四次推翻自己**（其中包括推翻我自己写的一个探测器）。

## 目录

```
getterms/               流水线本体
  config.py             语种注册、定价表、路径
  corpus.py             读 zip / 散装 json，语料审计与异常还原
  extract.py            锚定、校验、纠正重试、形态还原、交付归一化
  llm.py                客户端、重试退避、响应缓存
  run.py                主控：闸门链、并发派发、熔断、导出
  verify.py             交付门禁
  writer.py             xlsx / zip / 交付文档生成
  selfcheck.py          零成本自检（只读已落盘 dump）
  plural_lexicon.py     惯用复数清单（带出处）
  prompts/              三语提示词，各 8 个迭代版本
  tests.py              断言套件
e2e/                    端到端脚本（零 API 调用）
fixtures/               合成语料夹具
```

## 快速开始

```bash
pip install -r requirements.txt

# 断言套件 —— 不需要语料、不需要 key
python -m getterms.tests

# 端到端脚本 —— 同样不需要：它们用 fixtures/ 里的合成夹具
python e2e/e2e_delivery_columns.py
python e2e/e2e_row_order.py
python e2e/e2e_spend_breaker.py
python e2e/e2e_429_breaker.py
python e2e/e2e_balance_breaker.py
python e2e/destructive_cache_test.py

# 真跑一个语种（需要语料与 key）
python -m getterms.run --lang es --model <model> --effort high \
    --concurrency 40 --out out/full_es --dry-run
```

## 本仓库不含什么

- **语料本身** —— 第三方内容，版权不属于本项目。
- **模型的批量输出**（bake-off dump）—— 里面含语料原句。
- **密钥**。运行需要一个 key 文件或环境变量；断言套件与 `e2e/` **不需要**
  （它们从不发请求，用哑值即可）。
- **交付产物**（xlsx / zip）—— 同样含语料。

因此，**这个副本里的断言套件跑 540 条而不是 922 条**：依赖语料与 dump 的那几块
会**当场打印 `[跳过]` 并说明原因**（不是静默通过）。同一套代码在带语料的内部环境里
跑满 922 条。

## 公开副本与内部版的三处差异

1. `fixtures/` 是**自造**的合成语料（虚构的城市与博物馆），只为让 `e2e/` 能独立跑。
2. `e2e/*.py` 里多了两段：把仓库根加进 `sys.path`、给一个哑 key。
   两者都只为了让**任何人克隆下来就能跑**。
3. `tests.py` / `tests_fr.py` / `tests_ru.py` 里加了语料与 dump 的存在性守卫，
   缺了就**可见地跳过**而不是崩掉或静默通过。
